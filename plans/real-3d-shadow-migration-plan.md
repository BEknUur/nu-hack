# План Перехода На Реальный 3D С Солнцем И Тенями

## Цель

Перевести текущую карту из режима:

- `Leaflet + leaflet-shadow-simulator + OSM polygons`

в режим:

- настоящая 3D-карта
- наклон камеры
- объемные здания
- сохранение логики даты, времени, солнца и теней
- возможность дальше развивать inspector, sun exposure и аналитику

## Текущее Состояние

Сейчас проект работает так:

- карта рендерится через `Leaflet`
- тени и sun exposure считаются через `leaflet-shadow-simulator`
- рельеф берется из DEM `terrarium`
- здания загружаются через `Overpass API`
- выбранное здание показывается отдельно в локальном 3D viewer через `three.js`

Это хороший MVP, но не настоящий 3D-движок карты.

## Рекомендуемый Маршрут

Для первой полноценной 3D-миграции рекомендованный путь такой:

1. перейти с `Leaflet` на `MapLibre GL JS`
2. заменить `leaflet-shadow-simulator` на `mapbox-gl-shadow-simulator`
3. оставить текущую модель данных:
   - `date`
   - `sunExposure`
   - `terrainSource`
   - `getFeatures`
4. добавить нативные 3D-здания через `fill-extrusion`
5. только после этого решать, нужен ли еще более реалистичный режим на `Cesium`

## Почему Именно Этот Маршрут

Потому что он лучше всего сохраняет уже работающую продуктовую логику:

- текущая аналитика солнца не выбрасывается
- API мышления почти то же самое
- `getFeatures` и `terrainSource` остаются полезными
- можно переехать поэтапно, а не переписать все с нуля

Если сразу идти в `Cesium`, будет красивее, но риски выше:

- придется пересобирать почти весь UI карты
- тени и sun exposure придется заново валидировать
- интеграция будет сильно дороже

## Целевая Архитектура После Этапа 1

После первого большого этапа архитектура должна выглядеть так:

- `MapLibre GL JS` отвечает за карту, камеру, pitch, bearing, слои и 3D
- `mapbox-gl-shadow-simulator` отвечает за солнце, тени и sun exposure
- `Overpass API` продолжает отдавать здания
- `terrainSource` продолжает использовать DEM tiles
- текущий inspector переиспользуется поверх новой карты

## Какие API И Источники Данных Оставляем

### Оставляем

- `ShadeMap API key`
- `Overpass API`
- `Nominatim`
- `Terrarium DEM` или другой DEM источник

### Меняем

- `leaflet-shadow-simulator` -> `mapbox-gl-shadow-simulator`
- `Leaflet` -> `MapLibre GL JS`

### Позже можно улучшить

- перейти на `MapTiler Terrain RGB` или `Mapbox Terrain DEM`
- перейти с Overpass на более стабильный серверный кэш или precomputed dataset
- добавить vector tiles для зданий

## Что Будет С Тенями

### На Этапе 1

Тени и sun exposure должны работать концептуально так же, как сейчас:

- дата меняется через один shared state
- время меняется через один shared state
- shader/overlay обновляется через `setDate`
- режим sun exposure переключается через `setSunExposure`

### На Этапе 2

Поверх этого можно добавить:

- подсветку освещенной стороны выбранного здания
- цвет фасадов в зависимости от солнца
- 3D-подсветку для inspector panel

## Детальный План Работ

## Этап 0. Подготовка

### Цель

Подготовить код к миграции, не ломая текущий режим.

### Что сделать

1. Выделить слой абстракции для карты.
2. Разделить текущую логику на:
   - map engine
   - shadow engine
   - building source
   - selection state
3. Убрать прямую привязку UI к `Leaflet`-специфичным объектам, где это возможно.

### Результат

Появится возможность держать два режима:

- `Leaflet legacy mode`
- `MapLibre 3D mode`

## Этап 1. Внедрение MapLibre Без Теней

### Цель

Сначала завести 3D-карту саму по себе.

### Что сделать

1. Подключить `maplibre-gl`.
2. Создать новый хук, например:
   - `useMapLibreSetup`
3. Добавить новый компонент карты:
   - `MapLibreView`
4. Поднять базовый стиль карты:
   - light style
   - OSM/vector style
   - или MapTiler style
5. Настроить:
   - center
   - zoom
   - pitch
   - bearing
6. Подключить 3D-здания через `fill-extrusion`.

### Что важно

На этом этапе тени можно временно не переносить.

### Результат

Появится первый рабочий режим:

- карта в 3D
- здания объемные
- можно крутить камеру

## Этап 2. Перенос Теней На Новый Движок

### Цель

Сохранить существующую продуктовую логику солнца и тени.

### Что сделать

1. Подключить `mapbox-gl-shadow-simulator`.
2. Создать новый shadow hook, например:
   - `useMapLibreShadeSetup`
3. Перенести текущие настройки:
   - `apiKey`
   - `date`
   - `color`
   - `opacity`
   - `terrainSource`
   - `getFeatures`
4. Перенести обновления:
   - `setDate`
   - `setSunExposure`
   - `isPositionInSun`
   - `getHoursOfSun`
5. Проверить соответствие результатов со старым `Leaflet`-режимом.

### Результат

Новый 3D-режим начинает работать не только как красивая карта, но и как аналитический инструмент.

## Этап 3. Перенос Выбора Здания И Inspector

### Цель

Вернуть текущий UX выбора здания, но уже внутри настоящей 3D-карты.

### Что сделать

1. Добавить выбор здания через feature picking.
2. Реализовать `queryRenderedFeatures` по клику.
3. Находить выбранное здание по:
   - source layer
   - feature id
   - геометрии
4. Подсвечивать выбранное здание:
   - outline
   - более яркий extrusion color
   - glow или hover state
5. Привязать текущую `BuildingDetailsPanel`.

### Результат

Выбор здания будет происходить в самой 3D-карте, а не через отдельную 2D-сцену.

## Этап 4. Привязка Sun Inspector К 3D

### Цель

Сделать 3D действительно полезным для солнца.

### Что сделать

1. Для выбранного здания считать:
   - текущую освещенную сторону
   - приблизительный azimuth солнца
   - высоту солнца
2. В панели показывать:
   - facade in sun now
   - best side
   - morning vs evening
3. Подсвечивать фасады в 3D:
   - солнечная грань
   - теневой фасад
4. Синхронизировать с текущим time slider.

### Результат

Появится реальный 3D sun inspector, а не просто 3D-визуализация.

## Этап 5. Производительность И Надежность

### Цель

Чтобы режим был пригоден для реального использования.

### Что сделать

1. Ограничить частоту обновления `getFeatures`.
2. Кэшировать здания по bbox и zoom bucket.
3. Ограничить количество тяжелых зданий на экране.
4. Добавить graceful fallback:
   - если 3D режим не поддерживается
   - если теневой движок упал
   - если `Overpass` не ответил
5. Добавить telemetry:
   - время загрузки карты
   - время обновления теней
   - ошибки по feature loading

## Этап 6. Улучшение Реалистичности

### Цель

Сделать карту ближе к ощущению реального места.

### Что сделать

1. Добавить terrain в карту.
2. Добавить более качественный basemap.
3. Включить атмосферу, sky, light presets.
4. Улучшить цветовую схему теней и sun exposure.
5. Добавить camera presets:
   - top down
   - angled 3D
   - inspect mode

### Результат

Карта станет визуально ближе к реальному 3D-продукту, но при этом сохранит аналитику.

## Альтернативный Маршрут: Реалистичный Режим Через Cesium

### Когда это стоит делать

Только если цель именно такая:

- почти photorealistic city
- landmarks
- ощущение как Google Earth
- cinematic camera и exploration mode

### Что это значит

В этом случае делается отдельный режим:

- `Analytics Mode` на `MapLibre + shadow simulator`
- `Realistic Mode` на `Cesium`

### Почему не сразу

Потому что этот путь:

- дороже по времени
- хуже совместим с текущим шейдингом
- не лучший первый шаг для продукта, где важна аналитика солнца

## Порядок Реализации По Приоритету

1. Подготовить архитектуру под второй map engine
2. Поднять `MapLibre` без теней
3. Поднять 3D buildings
4. Перенести тени на `mapbox-gl-shadow-simulator`
5. Вернуть inspector и выбор здания
6. Привязать sun exposure к 3D UX
7. Только потом решать, нужен ли `Cesium`

## Критерии Готовности Этапа 1

Этап можно считать успешным, когда:

- карта работает в `MapLibre`
- есть pitch и 3D camera
- здания объемные
- дата и время переключаются
- тени снова работают
- inspector выбирает здание прямо в 3D
- UX не хуже текущего 2D режима

## Главные Риски

1. `mapbox-gl-shadow-simulator` может отличаться по поведению от текущего Leaflet-варианта.
2. `Overpass` может стать bottleneck при активном движении 3D-карты.
3. Высоты зданий в OSM по-прежнему местами неполные.
4. Понадобится аккуратно развести:
   - базовые 3D buildings
   - data layer для аналитики
   - выбранное здание

## Рекомендация

Следующий практический шаг:

1. не идти сразу в `Cesium`
2. начать миграцию на `MapLibre GL JS`
3. сразу проектировать все так, чтобы тени переносились через `mapbox-gl-shadow-simulator`

Это самый разумный путь, если цель:

- реальный 3D
- сохранение солнца и теней
- постепенная миграция без обвала текущего продукта
