# Отчёт: Тестирование rate limit shademap.app API

**Дата:** 29.03.2026
**API Key:** `almas.issakov.t@gmail.com`
**Endpoint:** `https://shademap.app/tiles/v1/shadow/{timestamp}/{z}/{x}/{y}.png`

---

## Методология

| Тест | Кол-во запросов | Режим |
|------|----------------|-------|
| 1 | 20 | Последовательно |
| 2 | 100 | Параллельно (одновременно) |
| 3 | 5000 | Параллельно, батчами по 500 |

Запросы использовали разные тайлы, временные метки и координаты, чтобы избежать кеш-хитов.

---

## Результаты

| Тест | Запросов | 200 OK | 429 | Другие | Время |
|------|----------|--------|-----|--------|-------|
| 20 seq | 20 | 20 | 0 | 0 | ~15с |
| 100 parallel | 100 | 100 | 0 | 0 | ~950мс |
| 5000 parallel | 5000 | 4505 | **0** | 495* | ~5 мин |

*495 "других" — невалидные временны́е метки в URL (артефакт генерации скрипта), не rate limit. При ретесте с корректными URL → 200.

---

## Заголовки ответа

```
cache-control: public, max-age=14400, must-revalidate
cf-cache-status: REVALIDATED
x-content-type-options: nosniff
```

Нет `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `Retry-After` — сервер не раскрывает лимиты в заголовках.

---

## Выводы

1. **Rate limit не обнаружен** при 5000 параллельных запросов — 429 не получен ни разу
2. **Cloudflare CDN** кеширует тайлы на 4 часа (`max-age=14400`) — повторные запросы к одному тайлу не доходят до origin-сервера
3. **Для парсинга данных** — ограничений нет при разумной нагрузке, параллельные запросы работают стабильно

---

## Рекомендации

- Добавить **debounce 300мс** на слайдер времени — не для защиты от лимитов, а для экономии трафика
- При массовом парсинге (десятки тысяч запросов) — добавить задержку ~50мс между батчами на всякий случай
- При получении 429 (если вдруг случится) — retry с exponential backoff от 1с
